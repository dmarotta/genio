# Unity unit enforcement

Unity units use `genio-unity` for compile, tests, import, build, Play, editor commands and console access. Its targets are the unit's own engine root and its live leased Play slot. The brief and bundled Unity skill explain that rule.

At every launch and respawn, Genio prepends a per-task `unit-bin` directory to PATH. `genio-unity.cmd` invokes the installed wrapper by absolute script path. `unity.cmd` shadows bare `unity`/`Unity`, prints the rule, records an incident and exits 21. The wrapper's real Unity CLI path is resolved before the shim is applied. Windows `Path` and `PATH` are replaced together. Missing guard files or config prevent a new Unity unit launch.

Claude units also receive a `PreToolUse` hook alongside the existing `Stop` hook. It covers Bash, PowerShell, Read, Edit, Write, Glob, Grep and NotebookEdit. The hook rejects direct Unity editor, Hub and CLI calls, raw editor flags, main-copy paths, and Pipeline descriptor reads outside the unit's live leased slot. Path checks resolve existing ancestors, including junctions and new files. Only git commands can explicitly refer to main-copy `.git` internals; that exception does not allow git commands on the main working tree or ordinary reads of its `.git` files. Rejections print a reason naming `genio-unity` and exit 2. Invalid config or malformed hook input also exits 2. The hook uses an argument vector to preserve special characters in paths, and `onFailure: block` also rejects a failed or timed-out hook on Claude Code 2.1.295 or later.

Claude's [hook reference](https://code.claude.com/docs/en/hooks#exit-code-2-behavior-per-event) defines exit 2 as blocking `PreToolUse`. Its [permission documentation](https://code.claude.com/docs/en/permissions#extend-permissions-with-hooks) places that hook before permission evaluation. The regression tests check a launch with `--dangerously-skip-permissions`, retain both hooks, and execute the shipped hook with a bypass-mode payload to verify exit 2. These are local tests, without a model session. Codex and other harnesses receive the shim and process watch; they have no confirmed equivalent pre-tool hook.

On Windows, Overwatch polls the process list every five seconds independently of its ordinary status cadence. The terminal exposes its actual PTY PID and the times before and after spawning it. The watch adopts a root only while that terminal is still live and its process creation time matches that spawn interval, then follows children born after their parents. It remembers observed descendants by PID and creation time across detach and reparenting. Only a proven unit descendant running a Unity editor outside the own-copy or live-lease targets can be stopped. The watch refreshes the snapshot and checks the creation time again on the same Windows process handle used to kill. It kills one editor process, never a process tree. Player editors, Toolbox, and unrelated editors on a unit worktree are not adopted or stopped. The real Unity CLI itself is excluded from editor detection.

A stopped editor adds a `note [key=unity-guard]` to the unit status file and sends the rule to its inbox. Hook, shim and watch incidents are appended to `<taskData>/unity/guard-incidents.jsonl`. The Gauntlet's `unity-guard` step examines those records and command-shaped lines in the unit terminal log before review or delivery. Findings go back to the unit. Audit cursors avoid repeating historical evidence after a fix round; a new identical attempt is still a finding. Incidents written after an audit remain unread until the next audit, including those written before that validation round ends.

The final handle check compares birth times at [CIM's microsecond precision](https://learn.microsoft.com/en-us/windows/win32/wmisdk/cim-datetime), retaining all 64-bit digits with integer/decimal arithmetic. A Windows regression test runs that code against an in-memory fake process object, including the extra 100 ns digit returned by `StartTime`; it never queries real processes.

A wrapper-recorded slot editor remains under the pool's authority after `--keep-editor` or a handoff to another unit. The watch verifies its recorded PID, project and registration time and leaves it to the pool's existing lifecycle checks. It also defers while that pool snapshot is unreadable. An unregistered unit editor receives no such exception. This prevents a retained editor from being stopped after another owner has acquired its slot.

Lease and pool editor checks read `placement.json` using the same mounted-volume fallback as the pool. Slots placed on the project's Dev Drive retain their allowed paths while lease state stays in Genio's data directory. These checks do not probe cloning capabilities or write pool state.

This is detection and denial, not a sandbox. Units share the player's account and can bypass PATH or encode commands beyond the hook's text checks. The watch fences editor targets; it does not verify wrapper provenance for editors on allowed targets. Polling can miss processes that disappear between snapshots, or a detached process whose ancestry was never observed. After an app restart the watch cannot reconstruct old unit ancestry. When ancestry or creation identity cannot be proven, it leaves the process alone. The watch is Windows-specific; tests inject fake process snapshots and fake termination only. No test enumerates or stops real Unity editors.
