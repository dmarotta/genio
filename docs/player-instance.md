# Player instance lifecycle (build 2)

The main process owns one player copy and editor per project window. They live outside the units' slot pool, leases, queue and cap. This is the service behind the [Play screen](play.md): IPC, frame/input MessagePort and the Settings → Unity & Play controls.

The final quest decisions supersede the Recon's earlier cap: the global player limit defaults to **2**, adjustable from 1–8. Idle time defaults to **10 minutes**, adjustable from 0–60. Lowering the cap leaves current editors alone. A start at the limit can close the oldest stopped, warm instance; it refuses while all instances are playing or busy. Units' slots are untouched.

## Play and Stop

`PlayerInstanceService.play()` mirrors a checkout's current files (including uncommitted and untracked files) or a git ref using `PlayerCopies`. It embeds `resources/unity/com.genio.play` **only in the marked player copy**, copying changed package bytes without churning timestamps on repeated Plays. The source checkout, unit worktrees and Toolbox are untouched.

For a warm editor, Play closes the previous stream, stops Play Mode, waits for the stopped state, calls `genio_sync_begin` (`DisallowAutoRefresh`), mirrors, reapplies the package, and calls `genio_sync_end` (`AllowAutoRefresh` and `Refresh`). The mirror's `beforeApply` hook closes the editor **before writing** source changes under Packages or ProjectSettings. A version change switches the Library stash while the editor is gone. Restarts and regular quits keep the same copy. Failed or cancelled hot mirrors attempt to resume auto-refresh.

Startup and reloads are polled for up to ten minutes. Status includes a bounded tail of `editor.log` (a screen fact for Genio) and, while Unity starts, the [start phase](#start-phases). Blocking hidden dialogs include title, text and buttons (Genio's screen facts carry them; the Play screen says only that a dialog blocks Unity). Compilation refusal uses Unity's current [`EditorUtility.scriptCompilationFailed`](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/EditorUtility-scriptCompilationFailed.html) flag; historical Pipeline console entries do not prevent replay after a fix. The console API targets this copy only. Play waits for Play Mode to be running before reporting `playing`; streaming can then begin.

Stop disconnects streaming and stops Play Mode, leaving Unity warm. The main process checks deadlines every five seconds without requiring an open Play surface. Zero minutes quits on Stop. Closing the Play port stops Play and starts the timer. Closing the project window quits its player editor. Stop, Quit, a newer Play and Genio exit cancel pending copies/startup so they cannot enter Play later.

## Start phases

A Unity start takes from about 20 s (a kept copy) to several minutes (a new copy). The Play status line names the phase, read from the editor's own log (`src/main/player-start.ts`). Before each launch, `launch()` moves the last session's `editor.log` to `editor.log.prev`, so an old "Loading completed" never reads as an instant start; if it cannot, phases are not read and the start behaves as before. While the instance is `starting`, `ready()` reads the new log forward from where its last read stopped, so no line is missed between polls. `StartPhases` maps Unity 6's markers to six phases:

| Phase (shown as) | Starts at |
|---|---|
| `opening` (opening) | the launch; the first domain reload belongs here |
| `packages` (unpacking packages) | `Application.AssetDatabase Initial Refresh Start`, only when the copy's `Library/PackageCache` was missing or smaller than the main checkout's at launch. UPM writes nothing until it finishes. |
| `compiling` (compiling scripts) | `[ScriptCompilation] Requested script compilation`, the `bee_backend` start or a Bee `[n/N]` line |
| `loading` (loading scripts) | `Begin MonoManager ReloadAssembly` after the refresh started |
| `importing` (importing) | `Domain Reload Profiling` after that reload, or an `Importing '` line outside a reload |
| `scene` (opening scene) | `Application.AssetDatabase Initial Refresh End` |

A recompile later in the refresh returns to `compiling`. `[Project] Loading completed` ends the start. A log without these markers stays on `opening`.

`status().start` carries `{ phase, bar? }` while `starting`. The bar (`startBar`) is set only when `player.json` holds `startDurations`, the time each phase took in this project's last start that reached "Loading completed". The previous phases' durations count as done, even ones this start skipped. Inside the current phase, a real count fills its segment: Bee's `[n/N]` (capped at N) while compiling; while unpacking, the copy's PackageCache bytes (sized every 5 s) against the main checkout's (sized once at launch). Without a count, time against that phase's last duration fills it, holding at the segment's end if the phase overruns. The bar stays below 100 until ready and never moves back. With no durations on record, the bar is absent and the screen shows it indeterminate. Leaving `starting` (ready, entering Play, compile errors, a failure, a stop) ends the phase; only a start that reached "Loading completed" replaces `startDurations`.

**Ready from the log.** A Pipeline call made while Unity loads can block for up to 20 s (15 s server-side). So once the log shows a known marker, a fresh start asks `editor_status` only after "Loading completed", which saves the 2–10 s a blocked call cost at the end. Before any marker (Unity has not written its log yet), Pipeline is asked every poll as before; those calls fail at once because no Pipeline port exists yet. If the log stays quiet for 30 s (UPM's silent resolve, or a Unity that words its log differently), Genio sends one background `editor_status` probe at most every 30 s, so a missing marker never strands a start. A warm editor's sync, Exit Play and Enter Play wait on Pipeline as before.

## Separate controls

The minimal Play screen drives one control per action. `startUnity()` copies and starts Unity, then stops in `ready` (edit mode, the only state with an idle deadline); it does nothing while the editor runs. `enterPlay()` (and the older `play()`) starts Unity first when it is off, in the same call, then syncs and enters Play. `exitPlay()` (and `stop()`) passes `exiting-play` back to `ready`. `stopUnity()` exits Play, quits the editor and keeps the copy through `editorGone()`, so the next start reuses its Library and incrementally syncs. Idle timeout (including zero minutes), Genio exit, crash cleanup and `quit()` retain the copy too. Only `deleteCopy()` explicitly requests deletion after verified editor shutdown; a stuck close retains the copy. A cold start checks the cap and memory **before** copying, so a refusal copies nothing.

`pause()` reads Unity's `playMode` before sending the toggling `editor_pause`. `step()` pauses first, then sends `genio_step`. On a step, the stream captures that frame and waits for its GPU readback inside it, so the frame is not one step late. The poll picks up a pause or stop made in Unity itself. `scenes()` lists build-settings scenes first, then the other `Assets/**/*.unity`. It asks Pipeline while the editor answers and reads the files otherwise. `setScene()` remembers the scene while Unity is off, opens it when ready, and re-plays into it while playing. `resize()` swaps Unity's stream session behind the same MessagePort, so a new resolution does not exit Play. Stream and input accept `paused`. `controls(state)` in `src/shared/play-controls.ts` maps every state to the toolbar's labels, enabled flags and actions.

## Shutdown and recovery

`<data>/player-copies/<key>/player.json` records the Genio owner PID and creation time, editor identity, root, source, version, state, deadline, observed process tree, peak working set and the last complete start's phase durations. `instance.json` remains the copy manager's record. `player.json` survives copy deletion to retain the memory estimate. Global settings are in `player-copies/settings.json`.

Only the recorded PID **and creation time**, opening the exact `-projectPath`, can be closed. Pipeline quit and helper `WM_CLOSE` precede a 30-second wait and a forced stop of the verified tree. Every force kill checks the creation time on the OS handle used to kill. Children are checked by creation time; shared licence clients and processes naming another project are excluded. An unverified or surviving editor produces `close-stuck`, retains the copy and requires another Quit. Startup protects those copies from the deletion sweep.

The Windows helper retains the editor's original handle and watches a pinned Genio owner handle. Two minutes after the owner disappears it posts `WM_CLOSE`, waits 30 seconds, then stops verified descendants and the original editor if needed. Visible recovery uses the same watched helper. A player launch is refused if it cannot retain a watchdog; unit-slot fallback behavior is unchanged. The helper writes `exit.json` and, when used, `watchdog.json` in its launch directory.

Genio exit requests all player editors to quit and shares the existing four-second application shutdown budget. It never awaits copy deletion. The next startup closes orphan editors before `PlayerCopies.sweep()`. Deletion remains marker-guarded, asynchronous and retryable; unfinished or locked copies stay pending and can be revived for the next Play.

`PLAYER_COPY_POLICY.keepCopyWhenEditorQuits` defaults to `true`. Startup adopts retained copies rather than deleting them with their previous session. Startup and an hourly timer run `PlayerCopies.cleanup()` in the background, with overlapping runs coalesced. Cleanup deletes unused copies whose `lastPlayedAt` is more than 24 hours old; copies never played use `createdAt`. Editor idle deadlines no longer schedule copy deletion.

Cleanup also checks free space on each copy's own volume (`statfs` on its copy directory, including copies on other drives). Below either 15 GiB available or 10% of volume capacity, unused copies are deleted least recently played first. Each deletion finishes before space is measured again, so block-cloned copies do not cause misleading estimates of reclaimed space. An unreadable volume does not trigger low-space deletion of recent copies.

Every cleanup checks live lifecycle state: a launch, queued or active operation, sync, stuck close or live editor PID/held lock protects the copy. Another live Genio's ownership also protects it. Eligibility is checked again after asynchronous disk/owner checks; deletion yields to a new lifecycle operation and `ensure()` can revive it. The hourly timer stops on shutdown, and cleanup cannot start another deletion while Genio exits. Cleanup leaves the Play screen's single status line unchanged.

## Quiet start

Disk contention ruined Play starts: a live compile took 59 s instead of 18 s while Genio copied a unit's `node_modules`, and UPM's package step took 254 s instead of 81 s during heavy writes. So while any player instance is `copying`, `syncing`, `starting` or `entering-play`, Genio holds back its own heavy background copies:

- **Unit `node_modules` setup** (`setupNodeModules` through `startWorktreeDeps`): the copy or `npm ci` waits. `deps.json` stays `installing` (with `waiting: 'a Play is starting'`), so the unit keeps waiting for `ready` and is never marked failed. The report records `deferredMs`.
- **Slot Library seeds** (`PlayPool.prepare`): a slot that needs a new clone or a Library seed waits before it starts copying. The slot stays `preparing` and keeps its lease. A switch of an already-seeded slot does not wait. `genio-unity`'s first Library seed of a unit's copy waits the same way and says so on its output.
- **Copy deletions** (`PlayerCopies`: explicit Delete copy, the daily and low-disk cleanup, the startup sweep and trash removal): a deletion waits before it starts. A running deletion pauses every 64 files, all workers together, and resumes where it stopped. Time spent paused does not count toward its 30-minute timeout. Reviving a copy (`ensure()`) aborts the wait at once.

The Play copy's own sync and first Library seed are part of the start and never wait. `PlayerInstanceService.state()` writes one marker per starting project, `<data>/quiet-start/<copy key>.json` (`resources/unit-skills/genio/lib/quiet-start.mjs`), with the start's begin time kept across its phases. Any other state (`ready`, `playing`, an error, a refusal, a stuck dialog, shutting down) removes it. A wait ends when no start is in progress, or after 10 minutes (`QUIET_CAP_MS`), whichever comes first. Waiters in the main process resume at once when a marker is removed; unit scripts poll every 2 s. A marker older than 10 minutes, or left by a Genio process that has exited, no longer counts. So a Play that never gets ready holds nothing back beyond the cap, and Genio exiting releases every hold. Nothing here waits on a unit, so a Play start cannot deadlock on a deferred copy. There are no settings, messages or buttons for it, and the Play status line is unchanged.

## Memory and streaming

A cold start is admitted before the copy: the editor cap, then available RAM (`os.freemem()`, standby included) against the project's learned steady working set (6 GiB on the first run) plus a 1 GiB reserve. When short, Genio first closes its own warm player instances and idle unit-slot editors, never the player's editors. Still short, Play stops at `low-memory` with the three biggest consumers by plain name; the Unity button becomes Start anyway (`startAnyway: true`) and Cancel (Stop) dismisses it. Only commit headroom below the estimate blocks even Start anyway. An existing refused copy stays available until daily or low-disk cleanup. The five-second monitor records the steady working set while playing or stopped warm (each session replaces the last) and the import peak separately. Settings displays player, unit-slot and running batch editor counts, working sets, and machine available/total RAM; the instance's own state shows on the Play screen only.

`playerInstanceStream` transfers one MessagePort to the owning project window. Unity credentials stay in main. The loopback WebSocket accepts one authenticated client, validates JPEG frames and complete input packets, and retains one latest frame. The MessagePort sends one frame per renderer credit. Port replacement cannot stop a successor session. Legacy input is view-only; Input System virtual keyboard/mouse/gamepad support and the corrected 30 fps cadence are restored from `4d08711^`.

Audio shares the socket. The package's optional `Genio.Play.Audio` assembly taps the active `AudioListener`, zeroes the hidden editor's own output (whatever the player's per-user Unity Mute Audio says, which nothing changes) and sends little-endian `GA` v1 packets: `'G' 'A'`, version 1, channels, seq u32, rate u32, frames u16, reserved u16, capture time f64 (Unix ms), interleaved int16 samples (see the package README). `PlayStream` checks a packet starting `GA` **before** the JPEG check and the 25 ms frame throttle: `validateAudio()` accepts version 1, 1–2 channels, 8–192 kHz, 1–4096 frames, a finite time and exactly the promised sample bytes; anything else closes the socket with 1003. Valid packets go to `onAudio` unthrottled and do not touch the frame throttle. `runtime()` carries `onAudio` through `stream()` and `resize()` like `onFrame`. The MessagePort posts `{ type: 'audio', bytes }` outside the frame credits: at most `AUDIO_IN_FLIGHT` (12, about 250 ms) packets the renderer has not acked with `{ type: 'audio-ack', count }`, then a backlog of `AUDIO_BACKLOG` (4) that drops its oldest packet, so a renderer that falls behind hears the newest sound. Renderer playback and the mute button are the next build; until then the renderer ignores audio messages.

Unit tool guards forbid player roots, including copies placed on another volume. Raw copy IPC cannot mirror under a running player editor; it must use lifecycle Play.

## A source that vanishes

Genio removes a unit's worktree and branch when it despawns the unit after a merge. That can happen at any moment of a Play, so the mirror is staged. `applyMirror` first reads every changed file into `.mirror-staging` beside the manifest, and that is the only step that reads the source. Only then does it remove and rename files inside the copy, which it never stops halfway. If the source vanishes while it is being read (a missing folder, `.git` link or worktree metadata, or a deleted branch, all detected by `sourceMissing`), the sync fails with `code: 'SOURCE_GONE'` and the copy keeps exactly what the previous sync left. Files already staged are reused by the next sync of the same content.

- **Copying or syncing:** `PlayerInstanceService` does not throw. A warm editor ends its hot sync and stays `ready`; a cold start ends `idle` with no Unity started. The status carries `sourceGone: { when: 'loading' }`, and the Play screen's status line says "This unit was removed." with **Play main**.
- **Unity starting, entering Play, playing:** the copy is independent, so everything goes on. `sourceGone: { when: 'running' }` is recorded for Genio's screen facts; the status line still says Playing. It is set by crew cleanup (`sourceRemoved`), and the five-second poll also checks the source.
- **The next Play, Restart or scene re-play:** a source that is already gone plays the main checkout, with `sourceGone: { when: 'fallback' }`.
- **Cleanup:** while a copy reads a checkout it holds a lease (`src/main/source-leases.ts`). Before removing a worktree, `crew.cleanup` waits up to 8 s for the read to finish. After that it stops the read (marked gone) and waits up to 10 s more, then removes the worktree anyway, so cleanup never hangs.
- **Picker:** it lists only checkouts with a `.git`. It reloads when the project's units change state and drops vanished checkouts (`playerSourceAvailable`, checked every 10 s). A request, pick or choice for a vanished source turns the status line into "That source is gone. Pick another one."
- **Unexpected errors** in the background poll are logged. The instance moves to `error` with the message (the status line says "Play failed." with **Try again**), except during Play, where only the message is set.

The unit page's **Play** (beside the primary action, under More at 720 px and below) appears for Builds in Unity projects. It is disabled once the worktree is gone; its tooltip is one short line and it shows no Play status. It opens Play with `unit:<id>` preselected as a one-shot request (`lib/play-nav.ts`, handed to the project's window through localStorage when needed) and does not start Unity.

## Verification

Run `npm run typecheck` and `npm test` with `GIT_CONFIG_*` variables removed (`Get-ChildItem Env:GIT_CONFIG* | Remove-Item` in PowerShell). Lifecycle tests use disposable repositories, fake process identities, fake Pipeline commands and a fake desktop API. `tests/quiet-start.test.ts` covers the quiet-start wait (deferral, resume on ready, resume on the cap, stale markers); the lifecycle, copy, pool and worktree tests cover the hold during a start, its release after a failed start, paused deletions and a deferred unit setup that completes. `tests/player-start.test.ts` replays excerpts of the Play start speed Recon's real logs (`tests/fixtures/play-start/`: a cold start and the second start of a kept copy) through the phase parser, and covers the bar mapping and its indeterminate fallback. The lifecycle tests feed the same excerpts through a fake editor: phases in order, no `editor_status` before "Loading completed", durations kept for the next start's bar, and the quiet-log probe. They never launch Unity. The helper can be compiled without running it. Real importing, graphics, licensing and virtual-input release latency require a later manual check in a disposable copy; no real Unity editor was launched for this build.
