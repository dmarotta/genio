# Inventory screen v1

Open Inventory with **Ctrl+9**, the folder icon in the rail, or a project's **Inventory** button. The project switcher remembers the last project; navigation from Projects takes precedence. Generate assets through the floating Genio panel. Per-project budgets, folder overrides and the Codex image switch are in Projects > project settings > Generation.

The hierarchy contains only indexed media, with recursive counts under the active filters. Select a folder to browse it and its descendants. **Ours** excludes vendor packs; **Vendor packs** and **All assets** reveal them with a circled-v badge. Search supports the index service's name/path matching and tokens such as `t:sfx`, `ext:png`, `in:UI`, `l:sprite`, `by:unit`, and `via:fal`. Type chips support multiple selections, tags are comma-separated, and Generated selects assets with Genio provenance. Sort by name, type, size or modification time.

Both grid and list request and render a bounded viewport with overscan. Only thumbnails that stay near the viewport for 120 ms request `genio-media://thumb` URLs, so fast scrolling queues no decodes; unsupported, large, missing and still-loading images retain a type icon. The screen renders at once from the cached index; during a project's first scan, the grid fills as pages are indexed and the empty state and footer show indexing progress. Opening a project starts its index watcher; switching projects or leaving Inventory closes it. Focus refreshes the index as a fallback. Requests from an old project, filter or asset cannot replace newer results.

The inspector uses native image, audio and video elements and, for glTF/GLB, FBX (binary and ASCII), OBJ with MTL, STL, PLY, Collada (.dae), BVH, USDA (and text .usd) and 3DS, a Three.js viewer. Images have zoom and scrolling; audio/video have native seek/play controls and looping. Unsupported codecs report an error. Every other file type (TGA and PSD images, .blend, USDZ and USDC, .anim and so on) says plainly that it cannot be previewed here and why, with Open in default app and Reveal: .blend needs Blender, which Genio does not run, and three r186's binary USD reader fails on USDZ and USDC. LFS pointers explain why the asset cannot be previewed.

The 3D viewer runs in a sandboxed frame (`genio-viewer://app/viewer3d.html`, `sandbox="allow-scripts"`, opaque origin, no preload) with its own CSP; the app window's CSP only adds `frame-src genio-viewer://app`. Three and its loaders load only there, when a model is selected, so the app bundle does not carry them. The frame reads one model and its side files (.bin, .mtl, PNG/JPEG/TGA/BMP/GIF/WebP/AVIF/KTX2 textures) and the model's own Unity `.meta` through a per-selection token, `genio-media://model/<token>/<file>`, confined to the model's folder and below, side-file types only, 64 MB per file (`src/main/model-viewer.ts`); it cannot reach IPC, `genio-media://world`, the network or other files. A texture path a model stores as the artist's own disk path is reduced to its file name, which main looks for (bounded) below the model's folder, the way Unity keeps a Textures folder beside its models. Draco, meshopt and KTX2 decoders ship with the app. Models over 64 MB are not loaded (the size and limit are shown), and a load that has not finished after 30 s is cancelled by removing the frame. Textures of every format but glTF are decoded in a worker (TGA in JavaScript, the rest with `createImageBitmap`), downscaled to 2048 px and flipped there, off the UI thread. Sizes are shown in metres: FBX units come from its UnitScaleFactor, Collada and USD from the file, and OBJ, STL, PLY, BVH and 3DS (which store no unit) are read as metres. FBX, Collada and USD files that say they are Z-up are turned upright on load; 3DS starts turned (Z-up by convention). FBX clips take their names and frame ranges from the model's Unity `.meta` when it lists `clipAnimations`. The viewer frames the model, orbits/pans/zooms, toggles wireframe, grid, bounds with dimensions, skeleton, clay and background, turns Z-up files upright, lists stats, format, units, clips (play, scrub, speed, loop, follow root) and textures (larger ones are downscaled to 2048 px), draws clay where textures do not resolve or decode, shows the skeleton of animation-only files (BVH, rig-only FBX/glTF) and pops out to a larger view. Each selection gets a fresh frame and every GPU resource is disposed when it closes. No project files are written by browsing. Copy path, open in the default app and open containing folder are explicit actions.

Successful Inventory opening and asset inspection unlock feature-tagged achievements. The backend's separate index achievement remains unchanged.

## Floating Genio panel

The project window shell (`App.tsx`) mounts one `GenioPanel` beside the stage, outside the per-screen content, so it stays on every screen except the main Chat screen (Comms), where it is hidden. It renders the same project `ChatPanel` as Comms: conversation history, queued messages, image paste, drafts, model/effort and approval controls are shared. Drag its header anywhere, or resize from its top-left or lower-right corner; arrow keys on each handle also work. There is no snapping. The panel is always clamped inside the stage, so shrinking the window pulls it back on screen and growing it restores the remembered layout. Collapse to a pill or use **Ctrl+Space**. The pill shows activity, new messages and queued counts, plus a generating count driven by `generation` events. Position, size and collapse state are saved per project in local storage. The panel's stage sits beside the pending answers (Your Move) column, so the two never overlap.

**Pop out Genio chat** opens a separate native desktop window that stays on top of other apps and is shown without taking focus. Move it outside Genio or onto another monitor and resize it with the OS window controls. Its bounds are remembered per project; it reopens only on a display that still shows its title bar, and is pulled back onto a remaining display when a monitor is removed or rearranged. The same mounted composer keeps its text, pasted images, removed chips and queued edits; the current screen still updates its live context. Model and image overlays open in the chat window. **Return chat** or closing the native window restores the panel without stopping units. Closing the project also closes the pop-out; drafts remain available in the project chat.

Screens publish what they show through `useScreenContext` (`lib/screen-context.ts`): a screen id plus short facts, such as the selected unit and its state in Squad, the edited quest in Quests, or the open Settings section. Inventory publishes its project, folder, preview, multi-selection and visible items through the same mechanism. The composer shows them as removable chips. Changing what is shown updates the chips; nothing is posted to the chat until the player sends a message. Ctrl/Command/Shift-click toggles up to 20 selected assets. Changing folders clears the old preview and selection. A dismissal applies to that chip value; browsing to another value restores it. Removing every chip sends no context.

`sendChat` accepts an optional context snapshot, carried through to `wksp.send`. It appends an escaped JSON `[screen: ...]` block containing the screen id, label and facts and, from Inventory, the project/engine/root and visible paths, kinds, sizes and compact provenance. The preview may add one cached 256-pixel WebP thumbnail through existing chat-image storage. Identical thumbnail bytes already delivered in this session are reused; queued, cancelled and unsent messages cannot suppress a needed thumbnail. Missing/unsupported previews and a full pasted-image attachment limit are recorded explicitly. Sent bubbles retain their own chips and thumbnail receipt. Editing a queued message restores that snapshot, including when editing from Comms, and never turns the automatic preview into a pasted attachment. Slow thumbnail preparation preserves send order. Sends with Inventory chips unlock **Shared View** (`inventory-chat`); sends with screen context unlock **Over the Shoulder** (`genio-panel`).

## Validation

`tests/inventory-ui.test.ts` covers filter/tree consistency, folder boundaries, pagination, bounded virtualization, thumbnail guards and preview fallbacks. `tests/inventory-screen.test.ts` exercises watcher ownership in StrictMode, project navigation, stale inspector requests, folder collapse and shared tree/grid filters. `tests/model-viewer-*.test.ts` and `tests/preview-unavailable.test.ts` cover the viewer protocol's path and type guards (including `.meta` and the texture search below the folder), frame messages, resource disposal, TGA decoding, Unity clip names, FBX frame rates, side-file URLs, the inspector's frame handling, size cap, timeout and the cannot-preview wording; `npm run test:e2e -- model-viewer` checks the frame in Electron (isolation probes, every glTF case and every other format from `tests/fixtures/models`, texture downscale and clay fallback, playback) and that 100 open/close cycles over all of them leave no GPU textures or geometries behind. `node tests/helpers/model-fixtures.ts` regenerates the 3DS and TGA fixtures, which Blender no longer writes. Existing backend tests cover indexing and file watchers; navigation and achievement guard tests cover the rail and palette.

`tests/inventory-context.test.ts`, `tests/screen-context.test.ts`, `tests/genio-panel.test.ts`, `tests/chat-popout.test.ts` and the Inventory cases in `tests/chat-queue.test.ts` cover the context registry, chip dismissal/live updates, snapshots and serialization, bounded selection, payload validation, thumbnail dedupe and limits, queued editing, send order, per-screen visibility, pointer drag/resize, clamping, collapse persistence, pop-out bounds and the feature achievements. Real-project capture scenarios should include floating, collapsed and resized chat on several screens, visible/removed chips and the model picker at narrow widths.

For UI checks, build and run `npm run capture -- <output-dir>` so the Base, both provider homes (including Claude secure storage), HOME fallbacks and Electron profile live in temporary directories. See the isolation rule in [performance.md](performance.md). `GENIO_CAPTURE_BASE` can supply a purpose-built fixture Base to copy into the sandbox. Optionally set `GENIO_CAPTURE_SCENARIOS` to a JSON file containing `{ "name": "capture-name", "script": "..." }` objects. Each script runs in the renderer and should await its DOM/media readiness before capture. Scenario failures save `scenario-failure.png`, report the error and exit nonzero. The normal nine-screen tour remains available without scenarios.
