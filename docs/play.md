# Play screen

Play (rail, Ctrl 0, or "Go to Play" in the command palette) appears only in a project window whose engine supports Unity slots (`supportsUnitySlots`). It drives the project's own player instance ([player-instance.md](player-instance.md)): one copy and one hidden Unity editor per project window, outside the units' slots. The screen is kept minimal: a header, one toolbar, one status line and the game.

- **Header**: the title, a compact source chip (`⎇ main ▾`) and a `⋯` menu. The chip's list keeps four groups: the main checkout, your worktrees, units' worktrees by unit name, and local branches played from their commits. Checkouts show their branch and uncommitted count; files are copied as they are on disk. Refresh sources is at the bottom of the list. Genio's own slot and player copies are never offered. A new source applies on the next ▶; while playing, it re-plays at once.
- **`⋯` menu**: Restart Unity, Open Unity visibly (debug), Unity console, and Idle time and editor limit… (Settings › Unity & Play, for all projects).
- **Toolbar**, driven only by `controls(state)` (`src/shared/play-controls.ts`):
  - **Unity button**: Start Unity (off, crashed) → Cancel (copying, starting) → Stop Unity (ready, playing, paused) → Stopping…. On low memory, Genio asks before copying and the button reads **Start anyway**. On a stuck dialog it reads **Restart Unity**; on an editor that would not close, **Close again**. Stop Unity keeps the copy until the idle time runs out, so the next start skips the copy.
  - **▶ / ■**: Enter Play (from Off it starts Unity first) and Exit Play, which stays pressed while Play runs.
  - **‖ Pause** (pressed while paused) and **⏭ Step**, which pauses first and advances one frame.
  - **Scene**: the build-settings scenes first, then the project's other scenes. While Unity is off the choice is kept for the next Play; while ready it opens; while playing Genio exits Play, opens it and enters again.
  - **Resolution**: 1280 × 720, 1920 × 1080, 960 × 540, 640 × 360 and 720 × 1280 portrait, remembered per project on this computer. A change while playing resizes the stream behind the same port, so Play continues. The canvas follows the chosen aspect.
  - Keyboard, as in Unity, while the game does not hold the keyboard: Ctrl+P toggles Play, Ctrl+Shift+P pauses, Ctrl+Alt+P steps.
- **Status line**: one line per state (`Unity is off`, `Unity ready`, `Playing · main @ 5de6fac · Arena`, `Unity closed unexpectedly (exit 1)`, the low-memory reason with the biggest consumers, the blocking dialog's title, `Compile errors · Show console`). While copying it becomes a progress bar and one line (`Copying · 120 of 253 MB · about 1 min left`); while Unity starts, an indeterminate bar with the last log line in its tooltip. In ready, a dim `quits in 9:12 if idle` suffix; clicking it keeps Unity open longer.
- **Live game**: the canvas fills the width up to the remaining height. Click it to send keyboard, mouse and gamepad through the Input System; Esc releases; Lock and Full screen. Games that read legacy input are view-only. Leaving the screen while playing exits Play and keeps Unity ready. A blocking dialog shows in place of the game with its text, buttons, screenshot and Open Unity visibly.
- **Console drawer**: opened from `⋯` or by itself on compile errors; polled while open and Unity runs.
- **Narrow windows** (≤ 520 px wide or ≤ 420 px tall): an icon-only Unity button with a tooltip, short resolution labels (720p, 1080p, 540p, 360p, Portrait), and Lock and Full screen as two icons on the canvas corner.

There is no Ask Genio button, lifecycle tracker, first-copy prompt, sync summary, Unity version, deletion text, idle callout or footer: the floating Genio chat receives all of it as screen facts (instance state and message, source, what is playing with the last sync, scene, resolution, Unity version, idle and copy deadlines, copy progress, the first copy's size, deletion, Unity's startup log, low memory, the blocking dialog, view-only input, errors and the last console error).

Achievements: Press Play (`play-first`), Motion Picture (`play-stream`, first live frame), Hands On (`play-input`, first held input), Big Screen (`play-fullscreen`), One Frame at a Time (`play-step`, a successful Step), Aspect Ratio (`play-resolution`, a resolution change while playing) and Field Test (`play-unit`, Play a unit's worktree). Step and resolution keep their old ids, so earned dates carry over. The old screen's package, snapshot, slot and takeover trophies stay retired.

Tests and screenshots use a fake player backend; no Unity editor is launched (`tests/play-screen.test.ts`, `tests/play-controls.test.ts`, `tests/player-sources.test.ts`).
