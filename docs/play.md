# Play screen

Play (rail, Ctrl 0, or "Go to Play" in the command palette) appears only in a project window whose engine supports Unity slots (`supportsUnitySlots`). It drives the project's own player instance ([player-instance.md](player-instance.md)): one copy and one hidden Unity editor per project window, outside the units' slots. The screen is kept minimal: a header, one toolbar, one status line (with one progress bar while working) and the game.

- **Header**: the title, a compact source chip (`⎇ main ▾`) and a `⋯` menu. The chip's list keeps four groups: the main checkout, your worktrees, units' worktrees by unit name, and local branches played from their commits. Checkouts show their branch and uncommitted count; files are copied as they are on disk. Refresh sources is at the bottom of the list. Genio's own slot and player copies are never offered. A new source applies on the next ▶; while playing, it re-plays at once.
- **`⋯` menu**: Restart Unity, Open Unity visibly (debug), Unity console, and Idle time and editor limit… (Settings › Unity & Play, for all projects).
- **Toolbar**, driven only by `controls(state)` (`src/shared/play-controls.ts`):
  - **Unity button**: Start Unity (off, crashed) → Cancel (copying, starting) → Stop Unity (ready, playing, paused) → Stopping…. On low memory, Genio asks before copying and the button reads **Start anyway**. On a stuck dialog it reads **Restart Unity**; on an editor that would not close, **Close again**. Stop Unity keeps the copy between sessions, so the next start reuses its Library and only syncs changed files.
  - **▶ / ■**: Enter Play (from Off it starts Unity first) and Exit Play, which stays pressed while Play runs.
  - **‖ Pause** (pressed while paused) and **⏭ Step**, which pauses first and advances one frame.
  - **Scene**: the build-settings scenes first, then the project's other scenes. While Unity is off the choice is kept for the next Play; while ready it opens; while playing Genio exits Play, opens it and enters again.
  - **Resolution**: 1280 × 720, 1920 × 1080, 960 × 540, 640 × 360 and 720 × 1280 portrait, remembered per project on this computer. A change while playing resizes the stream behind the same port, so Play continues. The canvas follows the chosen aspect.
  - Keyboard, as in Unity, while the game does not hold the keyboard: Ctrl+P toggles Play, Ctrl+Shift+P pauses, Ctrl+Alt+P steps.
- **Status line and progress bar**: the only place Play reports anything (`playLine` in `src/renderer/src/lib/play-screen.ts`). One plain word per state: Stopped, Preparing (copying or syncing the copy), Starting Unity, Starting Play, Ready, Playing, Paused, Stopping. A press answers at once (Preparing, Starting Play or Stopping) before the next status read. One progress bar sits beside the word only while preparing or starting: the copy's overall percentage when it reports bytes, else indeterminate. A problem turns the line red with one short sentence (Unity closed unexpectedly., A Unity dialog is blocking the editor., Unity would not close., The game has compile errors., Not enough free memory for Unity., This project's Unity version is not installed., Too many Play editors are open., Play failed., That source is gone. Pick another one., The live view stopped., This unit was removed., or Something went wrong. for a failed call) and at most one action: Try again, Open Unity, Show console, Settings, Reconnect or Play main. The technical message is the line's tooltip and a screen fact, never pushed.
- **Live game**: the canvas fills the width up to the remaining height. Click it to send keyboard, mouse and gamepad through the Input System; Esc releases; Lock and Full screen. Games that read legacy input are view-only (Lock is disabled, its tooltip says why). Leaving the screen while playing exits Play and keeps Unity ready. When the game is not running the area stays empty: no hint, no dialog panel, no stream note.
- **Console drawer**: opened from `⋯` or the status line's Show console, never by itself; polled while open and Unity runs.
- **Narrow windows** (≤ 520 px wide or ≤ 420 px tall): an icon-only Unity button with a tooltip, short resolution labels (720p, 1080p, 540p, 360p, Portrait), and Lock and Full screen as two icons on the canvas corner.

Nothing else reports Play: no toasts, desktop notifications, killfeed lines, chat messages, unit-page or Squad banners, Settings status line, idle countdown, copy sizes, file counts, sync summary, first-copy estimate, deletion text, source-gone notes or dialog panel (`tests/play-quiet.test.ts` guards the Play paths). The floating Genio chat receives the detail as screen facts: the status with the instance's message, source, a vanished source, scene, resolution, Unity version, Unity's startup log, the blocking dialog, view-only input, a closed live view, errors and the last console error. The unit page's Play button keeps one short tooltip.

Each project's copy survives idle editor shutdown, an editor crash, closing the project window and Genio exit. Idle time still controls when the running editor quits. Cleanup runs at Genio startup and hourly: an unused copy is removed after more than 24 hours since its last Play (since creation if never played). If its own volume has less than 15 GiB or 10% free, cleanup also removes unused copies least recently played first, stopping when space recovers. Launches, queued or active operations, syncs and live editor PIDs protect their copies. Explicit Delete copy remains available through the copy API and quits the editor before requesting deletion. Cleanup adds no Play screen status.

Achievements: Press Play (`play-first`), Motion Picture (`play-stream`, first live frame), Hands On (`play-input`, first held input), Big Screen (`play-fullscreen`), One Frame at a Time (`play-step`, a successful Step), Aspect Ratio (`play-resolution`, a resolution change while playing) and Field Test (`play-unit`, Play a unit's worktree). Step and resolution keep their old ids, so earned dates carry over. The old screen's package, snapshot, slot and takeover trophies stay retired.

Tests and screenshots use a fake player backend; no Unity editor is launched (`tests/play-screen.test.ts`, `tests/play-quiet.test.ts`, `tests/play-controls.test.ts`, `tests/player-sources.test.ts`).
